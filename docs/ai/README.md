# JDS AI 하네스 사용 안내

> 사람이 읽을 문서는 이 파일 하나입니다. `.claude/skills` 아래 파일은 AI가 읽는 지침이라 직접 읽지 않아도 됩니다.

JDS 컴포넌트를 AI와 함께 만들 때 쓰는 공유 지침입니다. "Select 만들어줘"처럼 짧게 요청해도 AI가 같은 순서로 조사하고, 질문하고, 구현하고, 검증합니다. Codex와 Claude Code 모두 저장소에 있는 같은 지침을 읽기 때문에 따로 설치할 것은 없습니다.

## 요청하는 방법

### 구현을 맡길 때

```text
JDS Select를 구현해줘.
Figma와 기존 코드를 먼저 확인하고 요구사항 초안을 보여줘.
```

Figma 링크나 이 컴포넌트를 쓸 화면을 알고 있다면 함께 알려 주세요. 요구사항을 처음부터 다 적을 필요는 없습니다.

### 코드는 직접 쓸 때

```text
코드는 내가 구현할게. API와 상태 시나리오를 먼저 정리해줘.
```

구현을 마친 뒤 "현재 변경분을 검토해줘"라고 요청합니다.

### 리뷰만 받을 때

```text
현재 변경분의 FF 품질을 검토해줘. 제품 코드는 수정하지 마.
```

리뷰만 요청하면 AI는 코드를 고치지 않습니다.

### 이어서 진행할 때

```text
디자이너 답변은 "부분 입력을 유지한다"야. 관련 구현과 스토리를 이어서 진행해줘.
```

```text
팝업이 열린 상태에서 disabled가 바뀌는 동작을 브라우저에서 확인해줘.
```

## AI가 일하는 순서

| 단계 | AI가 하는 일                                   | 요청한 사람이 할 일            |
| ---- | ---------------------------------------------- | ------------------------------ |
| 조사 | Figma, 사용처, 현재 코드를 먼저 읽습니다       | AI가 찾지 못한 자료만 알려줌   |
| 초안 | 확인된 요구사항과 AI의 제안을 나눠 보여줍니다  | 목적과 범위가 맞는지 확인      |
| 질문 | 결과가 달라지는 결정만 추천안과 함께 묻습니다  | 답변                           |
| 구현 | 코드, 스토리, 배럴, 체인지셋을 함께 작성합니다 | 직접 구현한다면 이 단계를 맡음 |
| 검증 | 바뀐 내용에 맞는 검사를 골라 실행합니다        | 결과 보고 확인                 |

명세가 충분하면 질문 없이 바로 구현합니다. 질문은 공개 API나 사용자 동작이 달라지는 결정에만 합니다. 답을 기다리는 동안에도 그 답과 상관없는 작업은 계속합니다.

## 결과 보고에서 먼저 볼 것

1. **열린 질문**: 답해야 다음으로 넘어갈 수 있는 결정입니다.
2. **핵심 지적**: 코드 품질이나 접근성에서 고칠 것을 최대 세 개까지 먼저 보여줍니다.
3. **확인하지 못한 것**: 도구나 시간이 없어 실행하지 못한 검사입니다. 통과한 검사와 따로 적습니다.

PR 설명도 AI가 씁니다. 리뷰어가 PR만 읽고 무엇이 왜 바뀌었는지 알 수 있게 쓰고, 디자인 문서에 없는데 함께 정한 결정은 "명세 외 합의사항"으로 따로 남깁니다. 커밋, 푸시, PR 생성은 요청했을 때만 합니다.

## 문제가 생겼을 때

**스킬이 목록에 보이지 않습니다.** 새 세션을 열어 봅니다. 그래도 없으면 "`.claude/skills/ject-jds-workflow/SKILL.md`를 읽고 적용해줘"라고 요청합니다. Claude Code에서는 `/ject-jds-workflow`, Codex에서는 `$ject-jds-workflow`로 직접 부를 수 있습니다.

**Figma나 브라우저 도구를 쓸 수 없습니다.** AI가 코드에서 확인할 수 있는 만큼 진행하고, 확인하지 못한 부분과 필요한 자료를 알려줍니다.

**다른 도구로 넘겨서 이어가고 싶습니다.** 긴 작업은 AI가 `.claude/jds-harness/_workspace/<작업명>/work.md`에 기록을 남깁니다. 이 폴더는 Git에 올라가지 않습니다. 다른 도구에서 이 파일 경로와 함께 "이어서 진행해줘"라고 요청합니다.

## 하네스를 고칠 때

| 위치                              | 내용                                           |
| --------------------------------- | ---------------------------------------------- |
| `.claude/skills/ject-jds-*`       | 스킬 원본, AI가 따르는 세부 절차               |
| `.agents/skills/ject-jds-*`       | Codex용 상대 링크, 원본과 같은 파일            |
| `.claude/agents`, `.codex/agents` | FF 리뷰와 브라우저 검증 역할의 진입점          |
| `packages/jds/AGENTS.md`          | JDS 코드 작성 규칙                             |
| `scripts/ai/check-harness.mjs`    | 링크, 문서에 적힌 경로와 명령, 메타데이터 검사 |

시작점은 [ject-jds-workflow](../../.claude/skills/ject-jds-workflow/SKILL.md)입니다. 다른 스킬은 여기서 단계마다 연결됩니다. 체인지셋, 타입, PR 템플릿 규칙은 기존 문서를 그대로 쓰고 하네스에 복사하지 않습니다.

하네스나 JDS 코드를 고친 뒤에는 저장소 루트에서 검사합니다. 문서에 적힌 경로나 `npm run` 명령이 사라졌으면 어느 문서에 적힌 무엇인지 알려줍니다. AI가 실제로 스킬을 고르는지는 확인하지 않습니다.

```bash
npm run check:harness
```

### 문체와 개선

| 문서                                                | 문체                        |
| --------------------------------------------------- | --------------------------- |
| 사람이 읽는 안내(이 문서), Storybook 문서, 체인지셋 | 합니다체                    |
| AI가 따르는 지침(`AGENTS.md`, 스킬, `docs/` 규약)   | 조건과 행동이 분명한 한다체 |
| AI의 결과 보고와 PR 설명                            | 해요체                      |

제품 문구는 Figma의 JDS Voice and tone 원칙을 따르고, 체인지셋은 [체인지셋 작성 규약](../changeset-guide.md)을 따릅니다.

하네스를 쓰다가 같은 문제가 반복되면 기존 규칙을 고칩니다. 사례마다 새 규칙이나 역할을 늘리지 않습니다. 하네스를 써 본 결과는 이 문서가 아니라 해당 PR 본문에 남깁니다.
