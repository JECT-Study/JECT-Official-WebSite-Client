# 공유 JDS 하네스 검증 결과

확인일은 2026-10-20이에요. 대상은 `dev` 기준 `codex/jds-component-harness`의 공유 하네스와 문서·운영 자료 정리 변경이에요. 아래는 하네스 구조와 가상 요청에 대한 응답 평가 결과예요. 실제 컴포넌트 구현이나 접근성 감사를 완료했다는 의미는 아니에요.

## 공유 구조와 연결

- 공유 스킬은 10개예요. 기존 개인용 JDS·FF 스킬 6개를 프로젝트용 이름으로 옮겨 보완하고, workflow·명세 조사·브라우저·패키지 스킬 4개를 연결했어요. 개인 스킬 원본은 수정하지 않았어요.
- 원본은 `.claude/skills`에 있고 `.agents/skills`는 저장소 안의 상대 링크예요. 개인 폴더가 없어도 원본을 읽을 수 있어요.
- 독립 FF·브라우저 역할 2개를 각 도구의 진입점으로 유지했어요. 나머지 별도 역할과 개인 스킬 설치 스크립트, JSON 실행 기록 검사기는 최종 구성에서 제외했어요.
- `node scripts/ai/check-harness.mjs`가 통과했어요. 스킬·역할 메타데이터, 저장소 내부 링크, 로컬 Markdown 참조, 개인 경로 누출 여부를 확인해요. 안내·평가·지침 파일 36개가 대상이에요. 전체 YAML/TOML 파서나 품질 판정기는 아니에요.
- 기존에 설치된 `js-yaml`로 스킬 10개와 Claude 역할 2개의 frontmatter를 파싱했어요. Python `tomllib`로 Codex 역할 2개를 파싱했어요. 두 형식 모두 필요한 필드를 확인했어요.
- skill-creator의 Python `quick_validate`는 현재 Python에 PyYAML이 없어 실행하지 못했어요. 새 의존성을 추가하지 않고 위의 YAML 파싱과 이름·설명 검사로 대체했어요.

## 개인 폴더 없는 복사본과 실패 경로

하네스 파일, 상대 링크와 연결된 저장소 가이드를 공백이 포함된 임시 경로에 복사했어요. 개인 스킬 폴더·설치 스크립트·`node_modules`는 복사하지 않았어요. 문서와 검사기를 새 위치로 옮긴 뒤 아래 검사를 다시 실행했어요.

| 조건                                      | 실제 결과        |
| ----------------------------------------- | ---------------- |
| 개인 스킬이 없는 독립 복사본              | 연결 검사 통과   |
| alias를 저장소 안 원본의 절대 경로로 연결 | 검사 실패로 거부 |
| alias를 상대 경로로 저장소 밖 원본에 연결 | 검사 실패로 거부 |
| 원본 스킬에 없는 로컬 참조 추가           | 검사 실패로 거부 |
| 스킬 description 제거                     | 검사 실패로 거부 |
| 임시 변경 복구                            | 연결 검사 재통과 |

최초 복사에서는 root AGENTS가 참조하는 체인지셋·타입 가이드를 빠뜨려 실패했어요. 이후 두 가이드를 포함했고, 최종 배치 검증에는 README가 참조하는 PR 템플릿도 함께 복사했어요. 실패 경로를 검사할 때 실제 checkout은 수정하지 않았어요. 심볼릭 링크를 일반 파일로 checkout하는 환경의 자동 인식은 별도 확인이 필요해요.

## 독립 행동 평가

[평가 사례](behavior-cases.md)의 A–E를 동일 입력으로 두 독립 평가자에게 제공했어요. 스킬 적용 실행은 현재 workflow와 필요한 저장소 스킬을 읽었고, 기준 실행은 가상 요청만 읽었어요. 기대 답이나 사전 의심 결함은 제공하지 않았어요. 둘 다 제품 소스 조사·수정·서버·설치·검사·브라우저·외부 게시 없이 응답 문안을 작성했어요.

| 사례                                     | 스킬 적용 실행                                                                                   | 기준 실행                                                   |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------ | ----------------------------------------------------------- |
| A: 짧은 선택 컴포넌트 요청               | 파일 목록과 실제 재사용 가능성을 구분하고 사용 장면·단일/복수를 우선 질문, 독립 조사와 책임 제안 | 같은 핵심 구분, 사용 장면·선택·검색·해제 질문과 재사용 조사 |
| B: 충분한 variant 명세와 상태 props 요청 | 브라우저 상태를 역제안하고 강제 제어 사례만 질문, variant 구현은 진행                            | 같은 판단, 강제 prop만 보류하고 외형 구현 진행              |
| C: PR 합의 선별                          | 부분 입력 유지 한 건만 합의로 선택, AI 제안·helper 이름·원문에 반영된 Escape 제외, 미검증 분리   | 같은 합의 선별과 열린 질문·검증 한계 구분                   |
| D: 유틸과 disabled 전환                  | 불변 주장 확인 후 제외 판단, 도구 부재와 제외 구분, 상태·FF·배포 검증 연결                       | 같은 핵심 구분, 함수·사용처 확인과 실제 상호작용 검증 계획  |
| E: 부분 재실행                           | HEAD가 같아도 dirty diff 재확인, 관련 계약·스토리·검증만 갱신하고 확정 형식 재질문 없음          | 같은 범위 유지와 수정 전 결과의 재사용 제한                 |

두 실행 모두 핵심 판단이 적절했어요. 적용 실행은 요구사항 분류·FF와 배포 검증 연결·범위 설명을 명시적으로 남겼어요. 소규모 정성 비교이므로 일반적인 품질 향상률이나 속도·비용 개선을 주장하지 않아요. 문서 위치 정리 후에는 행동 평가를 반복하지 않았어요.

최초 독립 구조 검토에서는 이전 로컬 구성의 검증 보고서와 세부 지침의 예전 개인 스킬 이름을 지적했어요. 현재 보고서로 교체하고 프로젝트 스킬 이름으로 통일했어요.

## 문서·운영 자료 정리 검증

- 동료용 진입점은 `docs/ai/README.md`, 역할 계약은 workflow의 `references/roles.md`, 검사기와 목록은 `scripts/ai`, 평가 자료는 `docs/ai/evals`로 정리했어요.
- 기존 체인지셋·타입 규약과 PR 템플릿은 옮기거나 복제하지 않고 README에서 연결했어요.
- workflow와 두 도구의 역할 파일에서 새 역할 계약을 가리키고, 검사기는 `docs/ai`의 Markdown도 확인해요. 이전 문서·검사·평가 경로가 공유 파일에 남지 않았는지 검색했어요.
- 별도 검토자가 이동한 경로와 참조를 읽기 전용으로 확인했어요. 저장소 루트와 다른 작업 디렉터리에서 연결 검사가 통과했고, 검토 범위에서 차단 문제는 발견하지 못했어요.

## 저장소 검사와 한계

- `npm run type-check`, `npm run lint`가 모두 exit 0으로 끝났어요. 최초 구성 검증에서는 JDS를 새로 실행하고 웹앱은 Turbo cache를 사용했어요. 최종 배치 검증에서는 두 워크스페이스 모두 cache를 사용했어요.
- 커밋 전 `npm run format`을 실행했어요. 기존 `.prettierignore`, `.gitignore`, `.git/info/exclude`를 CLI의 `--ignore-path`로 함께 적용해 생성물·개인 worktree·설정·실행 기록은 제외했어요. Prettier 설정은 변경하지 않았어요.
- [호출 경계 사례](routing-cases.json)는 적용 사례 10개와 전체 workflow 제외 사례 10개예요. 새 세션 자동 호출률은 측정하지 않았어요.
- 실제 Codex/Claude Code 앱의 새 세션 자동 선택·역할 등록·도구 권한은 파일 검사나 위 평가로 입증하지 않았어요. 명시적인 원본 `SKILL.md` 경로로도 지침을 읽을 수 있어요.
- 제품 코드·CI·의존성·버전은 변경하지 않았어요. Storybook·VRT·패키지 소비 빌드·실제 보조 기술은 이번 작업에서 실행하지 않았어요. 최초 실제 컴포넌트 작업에서 구현·검증 전체 흐름을 별도로 확인해야 해요.
