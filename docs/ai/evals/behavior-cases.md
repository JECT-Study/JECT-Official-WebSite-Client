# 하네스 행동 평가 입력

제품 수정·설치·외부 게시 없이 아래 독립 사례에 응답한다. 자료는 이 파일에 제공된 fixture이며 실제 JDS 명세·합의·실행 결과가 아니다. 요청과 원자료만으로 판단하고 확인하지 않은 사실은 구분한다.

## A. 짧은 구현 요청과 책임 제안

사용자: “JDS 선택 컴포넌트 만들어줘. 목적만 정해져 있고 상세 요구사항은 잘 모르겠어.”

제공 자료:

- 실제 사용 화면은 아직 전달되지 않았다.
- Figma에 목록의 기본·오류·비활성 외형이 있다. 단일/복수, 검색, 선택 해제 정책은 없다.
- 기존 SelectField와 Listbox가 있다는 파일 목록만 확인했다. 구현과 API는 아직 읽지 않았다.
- 새 외부 패키지·토큰 체계 개편을 요청하지 않았다.

구현 시작 전에 사용자에게 보낼 응답과 조사·질문·계속할 작업을 작성한다. 도구 실행이나 구현은 하지 않는다.

## B. 충분한 명세와 브라우저 상태

사용자: “이 명세대로 Button에 지정된 visual variant 하나를 추가해줘. isHovered, isFocused prop도 추가하면 편하겠어.”

제공 자료:

- variant의 토큰·크기·hover/focus-visible 외형과 이름·동작은 모두 명시돼 있다.
- 제품 사용 사례에서는 실제 포인터·키보드 조작에 따라 상태가 바뀌며 외부 강제 제어 사례는 제공되지 않았다.
- 현재 native button과 관련 CSS 상태가 있고 기존 props를 보존해야 한다.

추가 제안·질문과 바로 진행할 범위를 작성한다. 실제 구현은 하지 않는다.

## C. PR 합의 후보 선별

사용자: “PR 설명 초안의 리뷰어 참고 내용을 작성해줘.”

현재 디자인 문서:

- Escape로 팝업을 닫는다.
- 입력값 표시 형식은 YYYY.MM.DD다.
- 달력에서 선택하면 입력값도 갱신한다.
- 비활성 전환 중 닫힘·부분 입력의 blur 정책은 적혀 있지 않다.

작업 기록:

- 사용자 답변: “부분 입력 뒤 blur해도 내용을 유지하자. 이어 입력할 수 있어야 해.” 확정됐으며 현재 코드와 스토리에 반영했다.
- AI 제안: “비활성으로 바뀌면 팝업을 닫는 게 좋겠다.” 답변은 아직 없다.
- AI가 내부 helper 이름을 바꿨다. 별도 사용자 결정은 없었다.
- 이전 사용자 답변으로 Escape 닫힘을 확정했으나 현재 디자인 문서에도 반영됐다.
- 브라우저 검증은 실행할 수 없었다. 타입 검사만 통과했다.

공유 PR에 적을 짧은 목록과 남은 질문·검증 한계를 작성한다. PR 생성·게시를 하지 않는다.

## D. 검증 선택과 미검증 구분

사용자: “두 작업의 검증 계획을 구분해줘.”

1. 내부 날짜 파싱 유틸만 바꿨다. 외부 API·표시·입력·폼 동작은 그대로라는 것이 구현자의 주장이다. 배포 코드에 포함된다. 브라우저 도구는 없다.
2. SelectField 팝업이 열린 상태의 disabled 전환을 바꿨다. 배포 코드 변경이다. Storybook 빌드와 VRT는 통과했지만 키보드·폼·보조 기술은 실행하지 않았다.

각 주장에 추가 확인할 근거, 필요한 검증·제외 이유, 완료라고 말할 수 있는 범위를 작성한다. 검사를 실제로 실행했다고 주장하지 않는다.

## E. 부분 재실행과 이미 정한 결정

사용자: “디자이너 답변은 ‘부분 입력을 유지’야. 그 부분만 이어서 해줘.”

제공 자료:

- 기록과 현재 HEAD는 같지만 DateField 입력 핸들러에 미커밋 수정이 추가됐다.
- 기존 답변에서 표시 형식과 제출값 형식은 확정했다. 이번에는 바뀌지 않았다.
- 이전 브라우저 실행 결과는 수정 전 코드 대상이다.

재조사·구현·재검증 범위와 다시 묻지 않을 내용을 작성한다. 다른 동작·공통 토큰·전체 저장소 리팩터링으로 확대하지 않는다.

## 평가 방법

같은 입력으로 새 평가자의 스킬 적용 실행과 기준 실행을 비교한다. 적용 실행은 현재 workflow와 필요한 저장소 스킬을 읽고, 기준 실행은 이 입력만 읽는다. 평가자에게 기대 답이나 의심 결함을 미리 주지 않는다. 결과와 한계는 evaluation-report.md에 적는다. 이 평가의 응답은 실제 도구 사용·앱 자동 선택·컴포넌트 검증을 입증하지 않는다.

연결 검사 자체는 node scripts/ai/check-harness.mjs로 수행한다. 개인 스킬이 없는 임시 복사본에서도 실행하고, 링크 누락·저장소 밖 링크를 의도적으로 만든 임시 복사본에서는 실패해야 한다. 실제 checkout을 훼손하지 않는다.
