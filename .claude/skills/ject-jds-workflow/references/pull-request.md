# PR 작성과 명세 외 합의사항

PR 설명을 작성·수정할 때 현재 저장소의 PR 템플릿을 읽는다. 문제와 최종 사용자/소비처 동작, 필요한 변경 이유, 실제 검증과 한계를 먼저 설명한다. 초안 작성과 커밋·푸시·PR 생성·댓글 전송은 별도 행동이며 현재 사용자 권한을 따른다.

## 리뷰어에게 남길 결정

작업 중 질문·답변·결정 기록을 현재 Figma·디자인 문서와 다시 대조한다. 다음을 모두 만족하는 내용만 **명세 외 합의사항**으로 짧게 정리한다.

- 현재 디자인 문서에 설명되지 않았다.
- 사용자·디자이너 등 의사결정자의 실제 답변이나 명시적 승인으로 함께 확정했다.
- 동작·공개 API·지원 범위·검증에서 리뷰어가 알아야 하는 결정이다.

AI가 혼자 고른 내부 구현·추천·추정, 미해결 질문, 예제용 가상 합의는 넣지 않는다. 나중에 문서에 반영된 결정은 반복하지 않고 필요하면 해당 문서를 연결한다. 원문과 다르게 합의한 예외는 충돌과 승인 근거를 짧게 설명한다.

현재 템플릿의 리뷰 요구 사항 영역 등에 소제목을 추가한다. 각 항목은 결정한 내용 한 문장으로 적고 이유·제한이 중요할 때만 짧게 덧붙인다. 근거가 필요한 항목은 공유 가능한 노드·문서·스토리 링크를 연결한다. 개인 작업 기록의 절대 경로를 PR에 게시하지 않는다.

아래는 형식 예시이며 실제 합의가 아니다.

```markdown
### 명세 외 합의사항

- 날짜 일부를 입력한 뒤 포커스가 이동해도 입력 내용을 유지해요. 이어서 수정할 수 있도록 정했어요.
- 팝업이 열린 상태에서 비활성화되면 닫고, 편집 중인 값을 새로 확정하지 않아요.
```

항목이 없으면 이 소제목을 생략한다. 미결정이 리뷰에 영향을 주면 별도의 열린 질문으로 남기고 합의·완료로 표현하지 않는다. 기존 변경 요약·검증 결과를 이 목록으로 대체하지 않는다.

## 작성 전 확인

실제 최종 diff와 설명이 맞는지, 디자인 문서와 중복되지 않는지, 예시·AI 제안을 합의로 바꾸지 않았는지 확인한다. 검증 로그의 실행·실패·캐시·미검증을 구분한다. 이번 하네스·문서만 바꾸는 PR에 컴포넌트 동작 합의를 만들어 넣지 않는다.
