# 작업 기록과 재개

기본은 대화의 간결한 체크포인트다. 작업마다 파일을 만들지 않는다. 장기 작업·명세 질문 대기·큰 근거·Codex와 Claude Code 사이 인계에는 `.claude/jds-harness/_workspace/<작업명>/work.md` 하나에 계약·결정·진행을 합친다. 이 경로는 Git에서 제외한다. 브라우저 이미지나 긴 로그만 필요할 때 옆에 두고 링크한다.

```text
대상: repository / branch / HEAD / 수정·새 파일 / 확인 시점
범위: 사용자 요청 / 소유 파일 / 구현·설계·리뷰 / 권한
요구사항: 확인된 내용과 출처 / AI 제안 / 미결정
결정: 실제 답변·출처 / 이유 / 적용 범위 / 현재 명세 외 합의 후보
진행: 바꾼 코드·스토리·공개 계약 / 판단 근거
검증: 필요한 검사·제외 이유 / 실행·통과·실패·캐시·미검증 / 근거
남은 일: 의존 질문 / 다음 작업 / 필요한 도구
```

FF 전체 범위표나 브라우저 관찰이 길면 같은 기록의 뒤에 둔다. 별도 JSON, 완료 상태 스키마나 증거 해시 입력을 만들지 않는다. 기록 형식의 충족을 코드 품질 통과로 사용하지 않는다. 시크릿·불필요한 원문·개인 경로는 공유 자료에 넣지 않는다.

## 이어서 작업

다른 도구에는 이 기록의 절대 경로와 현재 요청을 전달한다. 두 앱이 자동으로 서로 실행되거나 메시지를 받는다고 가정하지 않는다.

현재 HEAD뿐 아니라 dirty diff·새 파일·변경 범위를 다시 읽는다. HEAD가 같아도 미커밋 코드가 달라질 수 있다. 관련 코드·요구사항·답변이 바뀌면 영향받은 판단·검증을 다시 수행하고, 그대로인 근거는 유효성을 확인해 재사용한다. 비교할 이전 근거가 없으면 유효하다고 추정하지 않는다.

인증·권한·한도 오류는 같은 조건으로 반복하지 않는다. 일시적인 읽기 오류는 원인을 확인하고 한 번 재시도한다. 가능한 독립 작업은 계속하고 빠진 검증을 남긴다. 새로운 답변·코드 수정 이후의 필요한 재검증은 수행한다.

사용자에게는 핵심 변경과 판단을 먼저 설명하고 상세 기록을 연결한다. PR 작성 시 현재 디자인 문서를 다시 대조해 명세 외 확정 결정만 추린다.
