# JDS 저장소 맥락

이 스킬은 JECT JDS 저장소와 그 worktree에 적용한다. 제품 파일과 규약은 현재 git root에서 확인한다. `packages/jds/package.json`의 이름과 workspace 구성이 JECT JDS가 아니면 적용하지 않는다. 외부 권고와 프로젝트에서 확정한 규약을 구분한다. 사용자의 최신 요청과 현재 `AGENTS.md`, 실제 코드를 우선한다.

## 현재 상태부터 확인

- 복합 설계·구현·리뷰의 실행 순서와 완료 판정은 [ject-jds-workflow](../ject-jds-workflow/SKILL.md)를 따른다. 같은 작업에서 이미 확인한 맥락은 재사용하며 스킬 사이를 재귀 호출하지 않는다. 단순 탐색에는 workflow를 로드하지 않는다.
- branch, HEAD, 작업 트리와 대상 PR의 base/head를 확인한다. 로컬 수정, 원격 PR 코드, 이미 머지된 코드를 구분한다.
- [저장소 지도](references/repository-map.md)를 읽고 필요한 경로를 현재 파일에서 확인한다. 버전과 스크립트는 manifest와 lockfile을 다시 확인한다.
- 설계는 `ject-jds-component-design`, 접근성은 `ject-jds-accessibility`, 토큰은 `ject-jds-tokens`, 코드/PR 리뷰는 `ject-jds-review`로 연결한다. 단순 경로 탐색에 전체 검토를 강제하지 않는다.
- 외부 지침을 적용할 때만 [외부 지침 적용 범위](references/external-guidance.md)를 읽는다.

## 체인지셋 규약 확인

체인지셋을 작성·수정·통합하거나 필요 여부·bump·분리 여부·게시된 리뷰를 판단하기 전에, 현재 git root의 `docs/changeset-guide.md` 원문 전체를 읽는다. PR/브랜치 리뷰에서는 검토 대상 head의 문서를 적용한다. 같은 작업에서 동일한 원문을 이미 확인했다면 재사용하되 저장소·대상 head·규약 내용이 바뀌면 다시 읽는다.

규약의 예외, 신규 컴포넌트 작성 방식, 소비처 영향과 bump 판단을 함께 확인한다. 스킬에 규약 내용을 복사하거나 과거 요약·리뷰 댓글만으로 판단하지 않는다. 원문을 단일 기준으로 두어 가이드가 바뀌면 이후 작업에도 최신 기준을 적용한다. 파일이 없으면 해당 저장소에서 위치를 찾아 확인하고, 찾지 못한 규약은 확인했다고 보고하지 않는다.

체인지셋만 다루는 요청은 이 절차와 요청된 변경·검증만 수행한다. 전체 컴포넌트 설계·FF·접근성 검사나 새 체인지셋 생성을 자동으로 요구하지 않는다.

## 작업 경계

- 소유한 컴포넌트와 요청 범위를 확인한다. 연결된 컴포넌트는 읽어 원인을 추적할 수 있지만 수정 권한을 추정하지 않는다.
- 기존 작업 트리와 다른 작업의 변경을 보존한다. 하네스 변경을 요청하지 않은 제품 코드·CI 수정으로 확대하지 않는다.
- 제품 코드를 바꾸면 현재 저장소 규약에 따라 스토리, 공개 배럴, 체인지셋, 검증을 마친다. 타입 선언은 `docs/type-convention.md`를 먼저 읽고, 체인지셋은 위 규약 확인 절차를 적용한다.
- 새 패키지, 의존성, 설정, CI, 커밋·푸시는 저장소의 승인 규칙과 이미 주어진 사용자 권한을 확인한다. 반복 확인을 요구하지 않는다.
- 검토만 요청받으면 파일·커밋·PR 댓글을 수정하지 않는다.

## 결과

현재 확인한 사실과 경로를 짧게 설명하고, 추정과 미검증 범위를 구분한다. 과거 메모나 스킬의 지도만으로 최신 상태를 단정하지 않는다.
