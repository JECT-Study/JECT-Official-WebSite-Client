# JDS Design Tokens

## 토큰 개요

JDS 디자인 토큰은 Figma 디자인 변수를 기반으로 생성됩니다.

색상, 간격, 크기, typography 등의 값은 CSS 변수로 제공되며, vanilla-extract 스타일에서 `vars`와 `textStyles`를 통해 타입 안전하게 사용할 수 있습니다. Figma의 이름과 구조를 가능한 한 유지하지만, 코드에서 사용하기 적합하도록 객체 경로와 속성명이 정규화됩니다. TextStyle은 별도의 생성 과정을 거쳐 vanilla-extract의 `StyleRule` 객체로 제공됩니다.

JDS 컴포넌트에서는 다음 원칙에 따라 토큰을 사용합니다.

- 색상은 primitive보다 semantic 토큰을 우선 사용합니다.
- 간격과 크기는 하드코딩하지 않고 scheme 토큰을 우선 사용합니다.
- typography 조합은 `textStyles` 또는 typography className 유틸을 사용합니다.
- 테마별 값을 컴포넌트에서 직접 선택하지 않습니다.
- 자동 생성된 토큰 파일은 직접 수정하지 않습니다.

## 🎯 기본 사용법

JDS 토큰은 vanilla-extract의 `.css.ts` 파일에서 사용합니다.

토큰으로 스타일을 생성하고, React 컴포넌트에서는 생성된 className을 적용합니다.

### 스타일 작성

```tsx
// example.css.ts
import { style } from "@vanilla-extract/css";
import { textStyles, vars } from "@jects/jds/tokens";

export const card = style({
  padding: vars.scheme.semantic.spacing["6"],
  borderRadius: vars.scheme.semantic.radius["4"],
  backgroundColor: vars.color.semantic.surface.shallow,
});

export const title = style(textStyles.title["2"]);
```

`vars`의 각 leaf는 실제 디자인 값이 아니라 CSS 변수 참조값입니다.

```tsx
vars.scheme.semantic.spacing["6"];
// var(--scheme-semantic-spacing-6)

vars.color.semantic.surface.shallow;
// var(--color-semantic-surface-shallow)
```

`textStyles`는 여러 typography 속성이 조합된 vanilla-extract `StyleRule` 객체입니다. 다른 스타일과 함께 사용할 때는 `style()`에 배열 형태로 전달할 수 있습니다.

```tsx
export const description = style([
  textStyles.body.md.normal,
  {
    marginTop: vars.scheme.semantic.spacing["4"],
    color: vars.color.semantic.object.neutral,
  },
]);
```

### 컴포넌트에 적용

```tsx
// Card.tsx
import * as styles from "./example.css";

export const Card = () => (
  <article className={styles.card}>
    <h2 className={styles.title}>JDS Design Token</h2>
    <p className={styles.description}>토큰을 사용한 카드입니다.</p>
  </article>
);
```

React 컴포넌트는 현재 테마나 디바이스 값을 계산하지 않고 `.css.ts`에서 생성된 className을 적용합니다. 실제 값의 선택은 CSS 변수에 맡깁니다.

## 📚 토큰 API

외부 소비자는 `@jects/jds/tokens`가 제공하는 `vars`를 통해 CSS 변수 토큰을 사용할 수 있습니다.

```tsx
import { vars } from "@jects/jds/tokens";
```

### vars.color.semantic

Light/Dark 테마에 따라 실제 값이 변경되는 semantic color입니다.

```tsx
vars.color.semantic.accent.normal;
vars.color.semantic.surface.standard;
vars.color.semantic.object.subtle;
vars.color.semantic.fill.normal;
vars.color.semantic.stroke.subtle;
vars.color.semantic.feedback.positive.normal;
```

컴포넌트의 의미와 상태는 가능한 한 semantic color로 표현합니다.

### vars.colorPrimitive

테마와 무관한 원시 color palette입니다.

```tsx
vars.colorPrimitive.primitive.flow["500"];
vars.colorPrimitive.primitive.red["500"];
vars.colorPrimitive.primitive.green["500"];
```

Primitive color는 semantic color를 구성하는 기반 팔레트입니다. 일반적인 컴포넌트 스타일에서는 `vars.color.semantic`을 우선 사용합니다.

### vars.scheme

컴포넌트의 간격, 모양, 투명도 등 UI 구조에 필요한 토큰입니다.

```tsx
vars.scheme.semantic.spacing["8"];
vars.scheme.semantic.radius["4"];
vars.scheme.semantic.strokeWeight["1"];
vars.scheme.semantic.opacity["36"];
vars.scheme.semantic.margin.md;
vars.scheme.semantic.position["4"];
```

Scheme 토큰은 Desktop, Tablet, Mobile에 따라 실제 값이 달라질 수 있습니다.

### vars.typo

fontFamily, fontSize, lineHeight, fontWeight, letterSpacing 같은 개별 typography 값을 제공하는 primitive 토큰입니다.

```tsx
vars.typo.primitive.typeface.body;
vars.typo.primitive.fontSize.body.md;
vars.typo.primitive.fontWeight.body.normal;
vars.typo.primitive.font.lineHeight.body.md;
vars.typo.primitive.font.letterSpacing.body.md;
```

일반적인 typography 조합에는 `textStyles` 또는 typography className 유틸을 사용합니다. `vars.typo`는 기존 TextStyle로 표현할 수 없는 개별 typography 속성이 필요할 때 사용합니다.

### vars.environment

동작 시간, easing, 그림자, 쌓임 순서와 관련된 토큰입니다.

```tsx
vars.environment.semantic.duration["100"];
vars.environment.semantic.motion.fluent;
vars.environment.semantic.shadow.raised;
vars.environment.semantic.zIndex.overlay;
```

```tsx
import { style } from "@vanilla-extract/css";
import { vars } from "@jects/jds/tokens";

export const popup = style({
  zIndex: vars.environment.semantic.zIndex.overlay,
  boxShadow: vars.environment.semantic.shadow.overlay,
  transition: `opacity ${vars.environment.semantic.duration["100"]} ${vars.environment.semantic.motion.fluent}`,
});
```

## 📝 Typography 스타일

JDS는 일관된 typography를 적용할 수 있도록 `textStyles`와 typography className 유틸을 제공합니다.

`textStyles`는 fontFamily, fontWeight, fontSize, lineHeight, letterSpacing을 조합한 vanilla-extract `StyleRule` 객체입니다. CSS 변수 참조 문자열을 제공하는 `vars`와 달리 하나의 TextStyle에 필요한 여러 CSS 속성을 함께 제공합니다.

### vanilla-extract 스타일에서 사용하기

`.css.ts`에서는 `textStyles`를 `style()` 또는 `recipe()`와 조합합니다.

```tsx
import { style } from "@vanilla-extract/css";
import { textStyles, vars } from "@jects/jds/tokens";

export const title = style([
  textStyles.title["4"],
  {
    color: vars.color.semantic.object.boldest,
  },
]);

export const description = style([
  textStyles.body.md.normal,
  {
    color: vars.color.semantic.object.neutral,
  },
]);
```

`textStyles`는 다음 구조로 제공됩니다.

**Title**

- `textStyles.title["1"]`부터 `textStyles.title["6"]`

**Label**

- `textStyles.label.{size}.{weight}`

**Body**

- `textStyles.body.{size}.{weight}`

**Syntax**

- `textStyles.syntax.{size}`

### React 컴포넌트에서 사용하기

React 컴포넌트에서 typography className이 필요할 때는 `@jects/jds/utils`가 제공하는 유틸을 사용합니다.

```tsx
import {
  getBodyClassName,
  getLabelClassName,
  getSyntaxClassName,
  getTitleClassName,
} from "@jects/jds/utils";

export const TypographyExample = () => (
  <section>
    <h2 className={getTitleClassName({ size: "lg" })}>섹션 제목</h2>

    <p className={getBodyClassName({ size: "md", weight: "normal" })}>
      본문에 사용하는 텍스트입니다.
    </p>

    <span className={getLabelClassName({ size: "sm", weight: "bold" })}>레이블</span>

    <code className={getSyntaxClassName({ size: "sm" })}>const jds = true;</code>
  </section>
);
```

Typography className 유틸은 내부적으로 동일한 `textStyles`를 사용하는 recipe를 기반으로 동작합니다.

### Title size와 TextStyle의 관계

생성된 Title TextStyle은 `1`부터 `6`까지의 단계를 사용합니다. React 컴포넌트에서 사용하는 typography 유틸은 이를 `2xl`, `xl`, `lg`, `md`, `sm`, `xs` size API로 제공합니다.

- `2xl` → `textStyles.title["6"]`
- `xl` → `textStyles.title["5"]`
- `lg` → `textStyles.title["4"]`
- `md` → `textStyles.title["3"]`
- `sm` → `textStyles.title["2"]`
- `xs` → `textStyles.title["1"]`

### Typography API 선택 기준

**`vars.typo`**

- 개별 fontSize, lineHeight, fontWeight 참조

**`textStyles`**

- `.css.ts`에서 typography 속성 조합

**`get*ClassName`**

- React 컴포넌트에서 typography className 적용

`textStyles`의 fontSize, lineHeight, letterSpacing은 typography CSS 변수를 참조합니다. 따라서 같은 TextStyle을 사용하더라도 viewport에 따라 실제 typography 값이 자동으로 변경될 수 있습니다.

## 💻 테마와 반응형

JDS 토큰의 테마와 반응형 처리는 CSS 변수 값의 교체를 통해 동작합니다. 컴포넌트는 동일한 `vars`와 className을 계속 사용하며, 테마 또는 viewport가 변경되면 브라우저가 새로운 CSS 변수 값을 적용합니다.

### 전역 토큰 스타일 로드하기

`JDSThemeProvider`는 JDS의 전역 토큰 CSS와 reset CSS를 로드합니다. 테마 상태를 관리하거나 런타임 theme 객체를 제공하지 않습니다.

```tsx
import { JDSThemeProvider } from "@jects/jds/theme";

export const App = () => (
  <JDSThemeProvider>
    <main>Application</main>
  </JDSThemeProvider>
);
```

컴포넌트의 `.css.ts`에서는 `vars`를 직접 참조합니다.

```tsx
import { style } from "@vanilla-extract/css";
import { vars } from "@jects/jds/tokens";

export const card = style({
  color: vars.color.semantic.object.bold,
  backgroundColor: vars.color.semantic.surface.shallow,
  borderColor: vars.color.semantic.stroke.subtle,
});
```

### Light/Dark 테마 전환

별도의 `data-theme` 속성이 없으면 light semantic color가 기본값으로 적용됩니다.

애플리케이션 전체에 Dark 테마를 적용하려면 일반적으로 `documentElement`에 `data-theme="dark"`를 설정합니다.

```tsx
document.documentElement.setAttribute("data-theme", "dark");
```

Light 테마로 돌아갈 때는 `light`를 설정하거나 속성을 제거할 수 있습니다.

```tsx
document.documentElement.setAttribute("data-theme", "light");

// light가 기본값인 경우
document.documentElement.removeAttribute("data-theme");
```

특정 영역에만 Dark 테마를 적용할 수도 있습니다.

```tsx
<section data-theme='dark'>
  <div className={styles.card}>이 영역에는 Dark semantic color가 적용됩니다.</div>
</section>
```

`data-theme`이 변경되어도 컴포넌트가 사용하는 토큰 경로는 바뀌지 않습니다. `vars.color.semantic`의 실제 값만 현재 테마에 맞게 교체됩니다.

### 반응형 토큰

Scheme과 typography 토큰은 viewport에 따라 CSS 변수 값이 자동으로 교체됩니다.

**Desktop**

- `1200px` 이상

**Tablet**

- `768px` 이상, `1199px` 이하

**Mobile**

- `320px` 이상, `767px` 이하

Desktop 값은 `:root`의 기본값으로 등록되고, Tablet과 Mobile 범위에서는 media query를 통해 해당 CSS 변수 값이 덮어써집니다.

다음 토큰이 반응형으로 동작합니다.

- `vars.scheme`
- `vars.typo`
- `textStyles`가 참조하는 typography 속성

```tsx
import { style } from "@vanilla-extract/css";
import { textStyles, vars } from "@jects/jds/tokens";

export const responsiveCard = style([
  textStyles.body.md.normal,
  {
    padding: vars.scheme.semantic.spacing["16"],
    borderRadius: vars.scheme.semantic.radius["8"],
  },
]);
```

위 스타일은 별도의 media query 없이도 spacing, radius, fontSize, lineHeight에 연결된 CSS 변수 값을 viewport에 맞게 적용합니다.

### 자동으로 바뀌는 범위

토큰의 반응형 처리는 토큰값을 변경하는 기능입니다. 컴포넌트의 레이아웃 구조까지 자동으로 변경하지는 않습니다.

예를 들어 `vars.scheme.semantic.spacing["16"]`의 실제 px 값은 자동으로 변경될 수 있지만, grid column 수나 flex 방향은 자동으로 변경되지 않습니다. 레이아웃 구조 자체를 변경하려면 별도의 media query를 작성해야 합니다.

JDS 내부 스타일에서는 생성된 `breakpoints.ts`를 사용할 수 있습니다.

```tsx
import { style } from "@vanilla-extract/css";

import { breakpoints } from "@/tokens/breakpoints";

export const layout = style({
  display: "grid",
  gridTemplateColumns: "repeat(3, minmax(0, 1fr))",

  "@media": {
    [`screen and (max-width: ${breakpoints.mobile.max}px)`]: {
      gridTemplateColumns: "1fr",
    },
  },
});
```

`breakpoints`는 현재 `@jects/jds/tokens` 배럴에 export되지 않는 JDS 내부 API입니다.

### 토큰별 변경 여부

**Dark 테마 대응**

- `vars.color.semantic` ✅

**반응형 대응**

- `vars.scheme` ✅
- `vars.typo` ✅
- `textStyles`가 참조하는 typography 속성 ✅

**고정 값**

- `vars.colorPrimitive`
- `vars.environment`

컴포넌트에서는 테마나 디바이스별 토큰을 직접 선택하지 않습니다. 항상 동일한 semantic 토큰을 사용하고 값의 선택은 전역 CSS 변수에 맡깁니다.

## 💡 Figma 매핑과 생성물 관리

JDS 토큰은 Figma에서 추출한 데이터를 입력으로 사용하고 `tokensBuilder.ts`를 통해 TypeScript 및 vanilla-extract 파일로 생성합니다.

### 전체 생성 흐름

```
Figma Variables
        ↓
src/tokens/input/token.json

Figma Text Styles
        ↓
src/tokens/input/textStyles.json

두 입력 파일
        ↓
tokensBuilder.ts + schema.ts
        ↓
tokens.ts
vars.css.ts
globalTokens.css.ts
textStyles.ts
breakpoints.ts
```

`token.json`은 color, scheme, typography, environment collection을 포함합니다. `textStyles.json`은 JDS에서 사용하는 typography 조합을 별도로 관리합니다.

### 입력 데이터 검증과 구조 변환

`schema.ts`는 입력 데이터의 구조를 검증하고 flat token 이름을 코드에서 사용할 수 있는 중첩 객체로 변환합니다.

```
semantic-spacing-6
        ↓
vars.scheme.semantic.spacing["6"]
```

숫자값에는 속성의 성격에 따라 필요한 단위가 추가됩니다.

- spacing, radius, fontSize 등의 값에는 `px`
- duration 값에는 `ms`
- opacity, fontWeight, zIndex 등은 단위 없이 유지

### 생성 파일과 역할

**공개 API**

- `vars.css.ts`: vanilla-extract CSS 변수 계약을 생성하며 `vars`로 공개됩니다.
- `textStyles.ts`: typography `StyleRule` 객체를 생성하며 `textStyles`로 공개됩니다.

**전역 스타일**

- `globalTokens.css.ts`: 기본값, Dark 테마, 반응형 CSS 변수 값을 할당하며 `JDSThemeProvider`를 통해 로드됩니다.

**JDS 내부 생성물**

- `tokens.ts`: 변환된 전체 토큰 구조의 스냅샷이며 현재 배럴에서 export하지 않습니다.
- `breakpoints.ts`: Desktop, Tablet, Mobile 범위를 제공하며 JDS 내부 스타일에서 사용합니다.

`vars.css.ts`가 생성하는 `vars`의 각 leaf는 CSS 변수 참조값입니다.

```tsx
vars.color.semantic.accent.normal;
// var(--color-semantic-accent-normal)
```

`globalTokens.css.ts`는 이 계약에 실제 값을 할당합니다.

- `:root`: primitive color, light semantic color, Desktop scheme, Desktop typography, environment
- Tablet/Mobile media query: 해당 viewport의 scheme과 typography
- `[data-theme="dark"]`: Dark semantic color

### Figma 이름과 코드 경로 매핑

일반 토큰은 Figma의 `/` 구분을 코드의 중첩 객체 경로로 변환합니다. 숫자로 시작하는 key는 문자열 bracket notation으로 접근합니다.

**color-semantic Collection**

- Figma: `semantic/accent/normal` → Code: `vars.color.semantic.accent.normal`
- Figma: `semantic/surface/standard` → Code: `vars.color.semantic.surface.standard`

**scheme Collection**

- Figma: `semantic/spacing/4` → Code: `vars.scheme.semantic.spacing["4"]`
- Figma: `semantic/radius/8` → Code: `vars.scheme.semantic.radius["8"]`

**color-primitive Collection**

- Figma: `primitive/flow/500` → Code: `vars.colorPrimitive.primitive.flow["500"]`

**typography Collection**

- Figma: `primitive/font-size/body/md` → Code: `vars.typo.primitive.fontSize.body.md`

**environment Collection**

- Figma: `semantic/duration/100` → Code: `vars.environment.semantic.duration["100"]`

### Semantic color 매핑

Figma의 semantic color에는 Light와 Dark 값이 각각 존재하지만 코드에서는 테마별 객체를 직접 선택하지 않습니다.

```tsx
vars.color.semantic.accent.normal;
```

Light와 Dark 모두 동일한 경로를 사용하며 실제 색상값은 `:root`와 `[data-theme="dark"]`에 할당된 CSS 변수에 의해 결정됩니다.

### TextStyle 입력 → textStyles 생성

TextStyle은 Figma Variables collection이 아니라 `input/textStyles.json`에서 별도로 관리합니다.

입력 파일에는 JDS에서 사용하는 TextStyle의 token과 typography 속성이 포함됩니다.

```json
{
  "textStyles": [
    {
      "token": "semantic-textstyle-body-md-normal",
      "type": "text",
      "fontFamily": "Pretendard Variable",
      "fontWeight": "400",
      "fontSize": "15px",
      "lineHeight": "24px",
      "letterSpacing": "0.04500000178813934px"
    }
  ]
}
```

TextStyle token은 category, size, weight 정보를 이름에 포함합니다.

```
semantic-textstyle-{category}-{size}-{weight}
```

- `category`: `title`, `label`, `body`, `syntax`
- `size`: category에서 지원하는 크기
- `weight`: Label과 Body에서 사용하는 굵기

Title과 Syntax는 weight 구분이 없으므로 size가 token의 마지막 항목이 됩니다.

빌더는 token을 category, size, weight로 나누고 중첩된 `textStyles` 객체로 변환합니다.

- 입력: `semantic-textstyle-title-6` → 생성: `textStyles.title["6"]`
- 입력: `semantic-textstyle-label-md-bold` → 생성: `textStyles.label.md.bold`
- 입력: `semantic-textstyle-body-md-normal` → 생성: `textStyles.body.md.normal`
- 입력: `semantic-textstyle-syntax-sm` → 생성: `textStyles.syntax.sm`

생성된 `textStyles`의 각 leaf는 다음 typography 속성을 포함하는 vanilla-extract `StyleRule`입니다.

- `fontFamily`
- `fontWeight`
- `fontSize`
- `lineHeight`
- `letterSpacing`

빌더는 TextStyle의 각 속성에 대응하는 typography primitive token이 있는지 확인합니다. 대응하는 primitive token이 있으면 생성된 `StyleRule`은 해당 CSS 변수를 참조합니다.

```tsx
// textStyles.body.md.normal
{
  fontFamily: "var(--typo-primitive-typeface-body)",
  fontWeight: "var(--typo-primitive-fontWeight-body-normal)",
  fontSize: "var(--typo-primitive-fontSize-body-md)",
  lineHeight: "var(--typo-primitive-font-lineHeight-body-md)",
  letterSpacing: "var(--typo-primitive-font-letterSpacing-body-md)"
}
```

대응하는 primitive token이 없는 속성은 `textStyles.json`의 입력값을 CSS에서 사용할 수 있는 형태로 정규화해 생성 결과에 포함합니다.

예를 들어 Syntax 계열은 별도의 letterSpacing primitive token이 없으므로 입력값을 변환한 결과가 `StyleRule`에 직접 포함됩니다.

```tsx
// textStyles.syntax.md
{
  fontFamily: "var(--typo-primitive-typeface-syntax)",
  fontWeight: "var(--typo-primitive-fontWeight-syntax-normal)",
  fontSize: "var(--typo-primitive-fontSize-syntax-md)",
  lineHeight: "var(--typo-primitive-font-lineHeight-syntax-md)",
  letterSpacing: "0em"
}
```

### 생성물 재생성

입력 파일이나 생성 로직을 변경한 후 다음 명령을 실행합니다.

```bash
npm run build:tokens --workspace=@jects/jds
```

재생성한 뒤에는 다음 항목을 확인합니다.

1. 예상한 생성 파일만 변경되었는지 확인합니다.
2. 기존 `vars` 또는 `textStyles` 경로가 의도치 않게 제거되지 않았는지 확인합니다.
3. category, size, weight 구조와 typography primitive 연결이 올바른지 확인합니다.
4. 컴포넌트와 Storybook에서 변경된 토큰이 정상적으로 표시되는지 확인합니다.
5. type-check와 lint를 실행합니다.

```bash
npm run type-check
npm run lint
```

## ⚠️ 사용 시 주의사항

- 컴포넌트에서는 primitive color보다 semantic color를 우선 사용합니다.
- 숫자로 시작하는 token key는 `["4"]`처럼 접근합니다.
- `.css.ts`에서는 `vars`와 `textStyles`를 사용합니다.
- React 컴포넌트에서는 typography className 유틸을 사용합니다.
- 테마나 디바이스별 값을 직접 선택하지 않고 동일한 semantic token 경로를 사용합니다.
- 반응형 토큰과 반응형 레이아웃의 책임을 구분합니다.
- `tokens.ts`, `vars.css.ts`, `globalTokens.css.ts`, `textStyles.ts`, `breakpoints.ts`는 직접 수정하지 않습니다.
